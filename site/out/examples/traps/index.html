Traps

A trap is a bug: deterministic, with a stable code, and it ends the program. Debug builds report file:line:column and the call trace, out of the machine code you ship.

Arithmetic#

long is checked. Overflow and division by zero are traps in every build mode — there is no --release that turns them off.

Bounds and keys#

Text#

Slicing a string checks UTF-8 boundaries, so a character cannot be cut in half.

Your own#

assert(condition) and trap(message) are builtins. trap never returns, so it may stand where a value belongs — which is what makes x else trap("…") the assert-unwrap.

Runaway recursion#

Call depth is a policy limit rather than a native stack accident: compiled code carries its remaining depth as a hidden argument and refuses the call that would exhaust it. Runaway recursion is a trap with a message and a stack, never a segmentation fault. The trace keeps the innermost frames and counts the rest.
