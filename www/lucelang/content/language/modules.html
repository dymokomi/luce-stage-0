import trace_math makes one sibling file available under one qualified name. The compiler loads that file once, resolves trace_math.twice, and then treats the call like any other typed function call.

Follow one import

The trace was built from two source files. MIR names the imported function, LLVM places both functions in one module, and optimization may inline twice across the original file boundary.

Two import namespaces

import std.math selects the compiler's embedded standard table. import math selects the project or sibling loader. The explicit std. prefix keeps the two namespaces stable as either one grows.

What an import binds

A normal import binds the final module name or an explicit alias. from name import a, b binds selected public declarations bare and leaves the module namespace unbound. Each binding participates in ordinary name-collision rules; imported privacy is checked on the import line.

Privacy is file-scoped

Declarations are public unless marked private. Public signatures use publicly nameable types. Struct and class bodies may use visibility regions for fields and members. Privacy controls name lookup; callers can still store and pass an opaque public value returned by a public function.

Aliases vanish before HIR

alias Name = Type creates another source spelling for the target. It works in type positions, constructors, member namespaces, imports, visibility, and chains. The alias shares the target’s nominal identity and runtime representation. Semantics resolves and erases it while diagnosing cycles, privacy leaks, collisions, and hidden double optionals.

Constants become immutable program roots

File scope contains declarations and const. Mutable state lives in function locals and object fields. Scalar constants fold once. Supported flat list, map, and rank-one array constants materialize as immutable per-runtime roots, using the ordinary object row with its immutable flag set.

Project and package identity

A luce.yaml project enables root-relative dotted modules and exact-version package requirements. The current resolver consumes local, store, shelf, and path packages. Package identity is separate from import spelling, so two roots remain distinct modules.
