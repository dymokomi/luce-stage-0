The compiler answers a chain of smaller questions. Where are the words? How are they nested? Which declaration does each name refer to? What work must the program perform? LLVM uses those answers to choose machine instructions.

The compiler contract

The public front end accepts root bytes, an optional module loader, and compile options. It returns either structured diagnostics or one verified mir.Program. The host supplies file bytes through the loader, while the source stage maps logical module names to loader requests.

Who decides what

Source loadingPrepares encoding, line endings, file limits, positions, module identity, and loader requests. LexingRecognizes spelling, indentation, token boundaries, unsafe controls, and recovery points. ParsingBuilds declarations, statements, and expressions according to the grammar. SemanticsResolves names, types, effects, flow, ownership, calls, and source-level errors. HIR and MIRTurn checked meaning into explicit operations, blocks, memory layouts, and cleanup. OptimizationRemoves unreachable and unread work while preserving semantic order and cleanup. Code generationLowers verified instructions to LLVM IR and emits the native object consumed by the linker.

What one stage hands to the next

Data moves forward through the pipeline: the AST feeds semantic analysis, HIR feeds lowering, and verified MIR feeds optimization and code generation. Each handoff has an explicit lifetime, so temporary parser storage can be released before the native backend starts.

AST is scaffoldingIt lives in a temporary arena and disappears after semantic analysis.
MIR is the front-end productIt can be verified on its own, printed deterministically, and serialized before native code generation.
Semantic diagnosticsName, type, flow, and ownership errors are reported while the source structure is still available.
Decoded MIR verificationLayouts, types, blocks, ownership claims, and indices are checked before a serialized module can execute.

How failure is contained

Lexing and parsing recover so a source file can report several useful mistakes. Semantic analysis accumulates bounded diagnostics and returns no runnable program when any exist. MIR verification failures become an internal-compiler diagnostic on generated programs; decoded modules are simply rejected as damaged or unsupported.

The front end has two results. Valid source produces verified MIR. Invalid source produces structured diagnostics with source locations.
