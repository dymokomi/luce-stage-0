You write functions, names, and if statements. The processor executes instructions such as lsl, cmp, and csel. This site follows how the compiler turns the first form into the second.

Start with one small program

Suppose we double a number and cap the result at ten. The number comes from the command line, so the final machine code performs the calculation while the program runs.

func clamp_double(value: i64, limit: i64) -> i64:
    let doubled = value * 2
    if doubled > limit:
        return limit
    return doubled

func main(args: list[str]):
    print(str(clamp_double(len(args), 10)))

There are two useful ways to read this program. From the top, it is a tiny story about a number. From the bottom, it is a set of storage choices, overflow checks, branches, calls, and cleanup. Luce’s compiler connects those views.

The machine-code result

After Luce has checked the program and LLVM has optimized it, the heart of clamp_double becomes these ARM64 instructions:

mov  x9, #0x4000000000000000 Load the signed safe-half boundary.
cmn  x8, x9                  Can doubling overflow?
b.mi overflow                 If so, take Luce’s trap path.
lsl  x8, x8, #1              Multiply by two with a left shift.
cmp  x8, #0xa                Compare the result with ten.
csel x8, x8, x9, lt          Choose the result or the limit.

LLVM uses a left shift because shifting by one doubles a binary integer. It uses csel because ARM64 can choose the capped result directly from the comparison flags. The preceding cmn and b.mi preserve Luce’s rule that signed overflow raises a trap.

The big picture

A compiler reaches assembly through a sequence of representations. Each stage answers a different question and records its answer for the next stage.

AST, HIR, MIR—three names worth keeping straight. The AST records the grammar you wrote. HIR records resolved names, types, calls, and ownership. MIR is the smaller instruction language handed to the LLVM backend.

How do we know both views agree?

People run the native path. The test suite also runs the same MIR through a separate interpreter. It compares output, errors, traps, files touched, and objects left alive. If the assembly path prints the right text but leaks a class, the test still fails.

Who implements each layer

The compiler and runtime are written in Zig. Most standard-library policy—JSON, paths, HTTP, ZIP, string algorithms—is ordinary Luce. LLVM optimizes and selects native instructions. The operating system links, loads, and supplies optional host services. The Luce ↔ Zig map names the boundary file by file.
