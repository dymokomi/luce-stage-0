# Constants and shared tables

`let` and `var` are local declarations. At file scope the word is
`const`: a value is folded when the program is compiled, and a flat
list, map or rank-1 array becomes one immutable object owned by the
program root.

```luce run
struct Entry:
    label: string
    fallback: long?

const WIDTH = 80
const NUMBERS: list(long) = [3, 1, 2]
const ALIAS = NUMBERS
const EQUAL: list(long) = [3, 1, 2]
const AGES = {"ada": 36, "alan": 41}
const METHODS = {0: "stored", 8: "deflated"}
const ORDER: array(long, _) = [16, 17, 18, 0]
const ENTRIES = [
    Entry(label = "missing", fallback = none),
    Entry(label = "present", fallback = 9),
]

func first(values: list(long) = NUMBERS) -> long:
    return values[0]

func main():
    let ada_age = AGES["ada"]
    let deflated = METHODS[8]
    print(f"{WIDTH // 2} {ada_age} {deflated}")
    print(f"{NUMBERS == ALIAS} {NUMBERS == EQUAL} {first()}")
    print(f"{ORDER.dim(0)} {ENTRIES[1].fallback else 0}")
    var editable = copy NUMBERS
    editable.sort()
    editable.append(4)
    print(f"{editable[0]} {len(editable)} {NUMBERS[0]}")
```

```output
40 36 deflated
true false 3
4 9
1 4 3
```

One written construction has one identity. `ALIAS`, every ordinary
use, an import, a lambda and the default of `first` all borrow
`NUMBERS`' one root. `EQUAL` is separately written and therefore a
different object even though its contents match. `copy NUMBERS` is
the deliberate door back to an ordinary owned, mutable list.

## What may be constant

Scalar and string values, enum members and object-free value structs
fold as before. A flat constant container may hold those same values;
an object-free struct may have an optional field, present or absent.

- A bracket literal is a `list(T)` unless an `array(T, _)` annotation
  makes it a rank-1 array. The literal supplies the array's length.
- An empty list or array needs its `list(T)` or `array(T, _)`
  annotation. The annotation supplies the missing type only: `T` must
  still be flat and non-optional even when `[]` has no elements.
- A container cannot contain another container in this version. A
  top-level optional element is refused too; put absence in an
  object-free struct field when it is part of the row.
- A `builder`, an object-carrying struct and a multidimensional array
  cannot be a constant container.
- General function and method calls, function values, and ownership
  verbs do not fold. The eight conversion constructors and `ord()` are
  explicit compile-time forms. Constants may refer to one another in
  any order, but never in a cycle.

This flat boundary is deliberate, not an accident of the parser. It
can be relaxed later without invalidating a program written today.

## Braces make maps

`{key: value, ...}` is a map literal everywhere an expression may
stand, not special syntax reserved for `const`. A runtime literal is
fresh and mutable. Its entries are evaluated in order; a later equal
key replaces the earlier value and keeps its insertion position.

```luce run
func main():
    var stock = {"fig": 3, "fig": 4, "pear": 2}
    stock["plum"] = 7
    for name, count in stock:
        print(f"{name}: {count}")
```

```output
fig: 4
pear: 2
plum: 7
```

Map keys are `long`, `string` or an [enum](../enums/); an unannotated
integer key lands on `long`. A constant map rejects a duplicate folded
key and points to both places it was written. A runtime map keeps
ordinary replacement semantics because its keys may be computed at
runtime.

Empty `{}` is not a literal: it says neither key nor value type. Write
`new map(K, V)` for an empty mutable map. The spelling also leaves an
empty-brace meaning available if Luce ever gains sets.

## The immutable boundary

The program root lives until its runtime is torn down. Reads and
iteration are legal. Slicing a constant list answers a fresh owned
list, as map `keys()` and `values()` answer fresh owned lists. Arrays
have indexing, iteration and `copy`, but no slice expression.

Every visible write is a compile error at the write: mutating methods,
`sort_by`, an indexed or nested store, and `file.read` into a constant
array. So is an ownership escape — `give`, `free`, returning the root,
or retaining it in another owner. The diagnostic recommends `copy`
when a mutable owned object is what was intended.

A plain parameter is a borrow, and the parameter's type does not carry
the fact that its caller passed a constant. That is the one static
boundary. Every runtime mutation path checks the row too, including
the inline stores generated by LLVM, and traps `immutable_object`
before it writes. There is no silent copy and no silently ignored
write.

Rows are materialized eagerly before user code. An unreachable row is
removed from the artifact; a reachable row is built once for each
runtime. A worker has a runtime of its own, so it gets roots of its own
rather than sharing an object across the worker boundary.

The exact declaration and refusal rules are in the
[statement reference](/ref/statements/#file-scope-constants), and the
ownership sentence is [S46](/ref/ownership/#s46).
