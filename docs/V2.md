# LuciaOS v2 — language first

> **Current as of `f333e12`.**  This is the north star: what v2 is for,
> what it is made of, and what order the work goes in.  Where it
> records a past decision it says so and keeps the wording of the day;
> where it states what is true now, the file that owns the detail is
> named beside it — `docs/PIPELINE.md` for the stages,
> `docs/ENGINE.md` for why there is one engine, `docs/CODEGEN.md` for
> the backend, `docs/MISSING.md` for the honest gap list.

v1 built the whole vertical: a persistent Fabric of Texels, typed
Fibers, capabilities, demand-driven evaluation, a C ABI, and Luce as
the evaluator language on top.  It worked, and it taught us the most
important lesson of the project: **Luce is the part that enables
everything else.**  Every other layer — storage images, texels,
fibers, access rights — made iteration slower while the language was
still growing.

v2 restarts from that first principle.  The v1 tree lives on the
`main-v1` branch and in `docs/v1/`; nothing is lost, and the Fabric
ideas return later on top of a language that has already earned them.

## The shape of v2

Two programs, one language module:

```text
luce  —  the compiler.   FILE.luc  ->  FILE.lc
loom  —  the environment that runs .lc programs.
```

- **`src/luce/`** is the language: indentation-aware lexer → parser →
  analyzer (typing + IR lowering) → verified Luce IR → one LLVM code
  generator, over `libluce_rt` (the semantics as a linkable library)
  — `docs/CODEGEN.md`.  The front end carried over
  from v1 intact, plus `module.zig`, which serializes verified IR as
  the front end's hand-over to the back end.
- **`src/apps/luce/`** is the compiler CLI: `build`, `check`, `ir`.
- **`src/apps/loom/`** is the terminal: a small colored shell that runs
  programs, plus the trusted host behind the Luce host builtins.
- **`programs/`** is userland, written in Luce.  The first citizen is
  the editor.

The language itself — values vs heap objects, collections, scope
ownership (`docs/OWNERSHIP.md`), scope, traps — is specified in
`docs/LANGUAGE.md`.

Ordinary OS files replace the v1 disk image.  Linux and macOS first;
network, braids, and synchronization stay deferred until the local
story is excellent.

## The artifact, and the seam behind it

**A `.lc` is machine code** — a tagged shared library `luce build`
writes and `loom run` opens with one `dlopen`, one symbol lookup and
one call.  Every artifact records the machine, the host ABI version, a
content hash of the program and the identity of the code generator
that produced it, so a foreign or stale one is refused by name rather
than run.  There is no fallback and nothing to fall back to
(`docs/ENGINE.md`).

Serialized IR still exists, one layer in: constants, struct layouts,
heap types, functions (locals, instruction pool, blocks) and the entry
point, versioned with a `LUCE` magic and a `u32`, currently 17.  It is
**a seam, not a deliverable** — the front end's hand-over to the back
end, and the artifact's cache key — and it is called `.lcm` when it has
to reach a disk, which is how `loom` gets a program compiled without
carrying a code generator.  `decode` re-runs the IR verifier so damaged
modules are rejected rather than run; any change to the instruction set
bumps the version and stale modules simply recompile from source.
Treat both like executables: the verifier checks structure, not intent.

> This section originally described a `.lc` that *was* the serialized
> IR, decoded and interpreted by `loom`.  That is the thing
> `docs/ENGINE.md` retired: the interpreter ships in nothing and
> survives only as the test suite's differential oracle.

## The host boundary

Luce stays pure: every effect goes through a builtin that the host may
or may not provide.  Programs compile with `allow_host`; a caller that
provides no host leaves the same program trapping instead of touching
anything.  loom is the trusted boundary that implements:

| builtin | shape | meaning |
| --- | --- | --- |
| `print(text)` | `String -> ()` | console line |
| `print_error(text)` | `String -> ()` | a line to standard error (sanitized) |
| `read_line(prompt)` | `String -> String?` | write the prompt, read a line; `none` at end of input |
| `env(name)` | `String -> String?` | one environment variable; `none` when unset |
| `clock_ms()` | `-> Int` | a monotonic reading; only differences mean anything |
| `sleep_ms(ms)` | `Int -> ()` | wait at least that long; already-elapsed waits return |
| `arg_count()` / `arg(i)` | `-> Int`, `Int -> String` | program arguments |
| `file_read(path)` | `String -> String!` | read a file |
| `file_write(path, text)` | `String, String -> !` | write a file |
| `file_append(path, text)` | `String, String -> !` | add to the end of a file |
| `file_delete(path)` | `String -> !` | remove a file |
| `file_rename(from, to)` | `String, String -> !` | move a file |
| `file_exists(path)` | `String -> Bool` | probe a file |
| `dir_list(path)` | `String -> List(String)!` | the names in a directory |
| `term_rows()` / `term_cols()` | `-> Int` | screen size |
| `term_clear()` | | clear the frame |
| `term_move(row, col)` | | position the cursor (0-based) |
| `term_style(fg, bg, bold)` | `Int, Int, Bool` | 256-color SGR; −1 = default |
| `term_write(text)` | `String` | draw text (sanitized by the host) |
| `term_flush()` | | present the frame |
| `key_read()` | `-> String` | block for one key ("text", "enter", "up", "ctrl_s", …) |
| `key_text()` | `-> String` | payload of the last "text" key |

The host owns raw mode, the alternate screen, buffering, and every
escape byte; a program can never emit control sequences directly on a
channel the host shares — `term_write`, `print_error`, and a
`read_line` prompt are all sanitized.  Standard output is deliberately
not: it is the program's own channel and may be a pipe or a file.  Raw
mode engages lazily on the first terminal builtin and is always
restored before a trap is reported — and before a `read_line`, because
a line read and a raw key loop are two ways to own one standard input
and only one of them can be live.  `key_read` and `sleep_ms` both
present the pending frame before they block, so a draw loop needs no
explicit flush.

Nothing bounds how long an interactive program runs;
the call-depth limit still catches runaway recursion.

## The editor

`programs/editor.luc` is the proof that the language is enough: a
modern terminal editor written entirely in Luce — movement, editing,
scrolling, line numbers, a status bar, save/quit, and per-line Luce
syntax highlighting (keywords, capitalized type names, builtins,
strings, numbers, comments).  Its source is embedded in the loom
binary, so `loom edit FILE` always works; `LOOM_EDITOR=path/to.luc`
swaps in a different editor without rebuilding, and
`loom run editor.lc FILE` runs a compiled one like any other program.

## What stays deferred

Fabric, Texels, Fibers, capabilities-as-values, Views, the Spool,
braids, multi-user anything.  The v1 fabric *intent* builtins, their
`allow_fabric` gate, and `fabric.zig` are gone from the compiler
entirely; the road back is `main-v1` and `docs/v1/`.

One deferral has been partly taken back, deliberately: a compiled Luce
artifact links against a published C ABI (`docs/CODEGEN.md`).  It is
host-only — one entry point and a table of the same effects the
terminal already implements, nothing like v1's surface — but it is
versioned in public and cannot be changed casually.

## Roadmap

Done so far: collections + conversions (`docs/LANGUAGE.md`), modules
(a file is a module), methods and the string/sequence library, and
**Phase 1 — ownership, implemented**: `docs/OWNERSHIP.md` S1–S43 is
live end to end (`give`/`copy`, give-parameters, the keeping rule,
scope-owned release with early-exit unwinding, statement
temporaries, container adoption, deep copy, late `var name: Type`
declarations, the `not_owned` runtime backstop), proven by the
numbered suite in `src/luce/specs/ownership_spec.zig`.  `free` is now a
rarity — deliberate early release only — and nothing can leak.

**Phase 2 — global scope, implemented**: top-level `let` declares a
compile-time constant (folded literals, arithmetic, string concat,
comparisons, conversions, value-struct construction, cross-constant
and cross-module references with cycle detection), inlined at every
use site — the editor's Theme workaround is gone.  Top-level `var`
stays out until a real program demands mutable file scope.

1. ~~**Phase 3 — errors.**~~  **Complete** (docs/LANGUAGE.md).  `T?`
   is a distinct type with no implicit nullability, flow-sensitive
   narrowing and `else`; `T!`, `try`, `catch` and `error(...)` are the
   recoverable-error story designed beside it in docs/FAILURE.md, and
   both halves are shipped.
2. Rebuild the editor's buffer on `List(String)` lines and a
   `Builder` frame — the collections exist now.
3. Grow the terminal: mouse, bracketed paste, incremental drawing
   (damage tracking in the host, same builtins).
4. More userland: `fmt.luc`, `grep.luc`, a file browser
   (`docs/CODEGEN.md` ranks the rest).
5. ~~**Finish code generation.**~~ **Done.** The LLVM backend is the
   only engine, and the lowering is **total**: integers, floats,
   Strings, structs, all four container kinds, `T?`, `T!`, ownership
   and every host service lower, and every `.unsupported` left in
   `lower.zig` refuses IR that could only arrive damaged. A `.lc`
   *is* machine code and `loom run` is one `dlopen`
   (`docs/CODEGEN.md`, `docs/ENGINE.md`). What is genuinely left of
   this item is smaller and named in `docs/CODEGEN.md`:
   cross-compilation (`--target`, one `libluce_rt` per target) and
   sharing one `libluce_rt` between artifacts instead of copying it
   into each.
6. Then — and only then — persistence and the return of the Fabric.
