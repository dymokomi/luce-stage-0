# LuciaOS v2 — language first

This is the north star: what v2 is for, what it is made of, and what
order the work goes in.  Where it states what is true now, the file that
owns the detail is named beside it — `docs/PIPELINE.md` for the stages,
`docs/ENGINE.md` for why there is one engine, `docs/CODEGEN.md` for the
backend, `docs/MISSING.md` for the honest gap list.

The project's first principle is that **Luce is the part that enables
everything else.**  A storage layer, access rights, or a sync protocol
built before the language is ready only makes iteration slower while the
language is still growing.  So the language comes first, and every layer
above it arrives on top of a language that has already earned it.

## The shape of v2

Two programs, one language module:

```text
luce  —  the compiler.   FILE.luc  ->  FILE.lc
loom  —  the environment that runs .lc programs.
```

- **`src/luce/`** is the language: indentation-aware lexer → parser →
  analyzer (typing + IR lowering) → verified Luce IR → one LLVM code
  generator, over `libluce_rt` (the semantics as a linkable library)
  — `docs/CODEGEN.md`.  The front end carried over
  from v1 intact, plus `module.zig`, which serializes verified IR as
  the front end's hand-over to the back end.
- **`src/apps/luce/`** is the compiler CLI: `build`, `check`, `ir`.
- **`src/apps/loom/`** is the terminal: a small colored shell that runs
  programs, plus the trusted host behind the Luce host builtins.
- **`examples/`** is userland, written in Luce.  The first citizen is
  the editor.

The language itself — value and reference types, collections, the
memory model (`docs/MEMORY.md`), scope, traps — is specified in
`docs/LANGUAGE.md`.

Ordinary OS files are the storage substrate.  Linux and macOS first;
network, braids, and synchronization stay deferred until the local
story is excellent.

## The artifact, and the seam behind it

**A `.lc` is machine code** — a tagged shared library `luce build`
writes and `loom run` opens with one `dlopen`, one symbol lookup and
one call.  Every artifact records the machine, the host ABI version, a
content hash of the program and the identity of the code generator
that produced it, so a foreign or stale one is refused by name rather
than run.  There is no fallback and nothing to fall back to
(`docs/ENGINE.md`).

Serialized IR still exists, one layer in: constants, struct layouts,
heap types, functions (locals, instruction pool, blocks) and the entry
point, versioned with a `LUCE` magic and a `u32`.  It is
**a seam, not a deliverable** — the front end's hand-over to the back
end, and the artifact's cache key — and it is called `.lcm` when it has
to reach a disk, which is how `loom` gets a program compiled without
carrying a code generator.  `decode` re-runs the IR verifier so damaged
modules are rejected rather than run; any change to the instruction set
bumps the version and stale modules simply recompile from source.
Treat both like executables: the verifier checks structure, not intent.

> This section originally described a `.lc` that *was* the serialized
> IR, decoded and interpreted by `loom`.  That is the thing
> `docs/ENGINE.md` retired: the interpreter ships in nothing and
> survives only as the test suite's differential oracle.

## The host boundary

Luce stays pure: every effect goes through a builtin that the host may
or may not provide.  Programs compile with `allow_host`; a caller that
provides no host leaves the same program trapping instead of touching
anything.  loom is the trusted boundary that implements:

| builtin | shape | meaning |
| --- | --- | --- |
| `print(text)` | `string -> ()` | console line |
| `print_error(text)` | `string -> ()` | a line to standard error (sanitized) |
| `read_line(prompt)` | `string -> string?` | write the prompt, read a line; `none` at end of input |
| `env(name)` | `string -> string?` | one environment variable; `none` when unset |
| `clock_ms()` | `-> long` | a monotonic reading; only differences mean anything |
| `sleep_ms(ms)` | `long -> ()` | wait at least that long; already-elapsed waits return |
| `file_read(path)` | `string -> string!` | read a file |
| `file_write(path, text)` | `string, string -> !` | write a file |
| `file_append(path, text)` | `string, string -> !` | add to the end of a file |
| `file_delete(path)` | `string -> !` | remove a file |
| `file_rename(from, to)` | `string, string -> !` | move a file |
| `path_kind(path)` | `string -> int!` | what is at a path: 0 nothing, 1 file, 2 directory, 3 other; links followed |
| `dir_list(path)` | `string -> list(string)!` | the names in a directory |
| `term_rows()` / `term_cols()` | `-> int` | screen size |
| `term_clear()` | | clear the frame |
| `term_move(row, col)` | | position the cursor (0-based) |
| `term_style(fg, bg, bold)` | `int, int, bool` | 256-color SGR; −1 = default |
| `term_write(text)` | `string` | draw text (sanitized by the host) |
| `term_flush()` | | present the frame |
| `key_read()` | `-> string?` | block for one key ("text", "enter", "up", "ctrl_s", …); `none` at end of input |
| `key_text()` | `-> string` | payload of the last "text" key |
| `os_total_memory()` | `-> long` | bytes the machine has |
| `os_available_memory()` | `-> long` | bytes it could still hand out |
| `os_cpu_count()` | `-> int` | logical processors |
| `exit(status)` | never returns | end the run with that number |

The host owns raw mode, the alternate screen, buffering, and every
escape byte; a program can never emit control sequences directly on a
channel the host shares — `term_write`, `print_error`, and a
`read_line` prompt are all sanitized.  Standard output is deliberately
not: it is the program's own channel and may be a pipe or a file.  Raw
mode engages lazily on the first terminal builtin and is always
restored before a trap is reported — and before a `read_line`, because
a line read and a raw key loop are two ways to own one standard input
and only one of them can be live.  `key_read` and `sleep_ms` both
present the pending frame before they block, so a draw loop needs no
explicit flush.

Nothing bounds how long an interactive program runs;
the call-depth limit still catches runaway recursion.

## The editor

`examples/editor/editor.luc` is the proof that the language is enough: a
modern terminal editor written entirely in Luce — movement, editing,
scrolling, line numbers, a status bar, save/quit, and per-line Luce
syntax highlighting (keywords, capitalized type names, builtins,
strings, numbers, comments).  It is also the first program to carry a
**dependency**, drawing through the `termui` package
(docs/TERMUI.md).  It is an ordinary installed program — `loom run
editor.lc FILE` starts it like any other artifact, and the build also
produces a standalone `editor` command.  (Loom carried an embedded
copy and a `loom edit` command until 2026-08-12, when the owner
retired both: an editor is a program a person installs.)

## What stays deferred

Persistence images, capabilities-as-values, views, network sync,
braids, and multi-user anything.  Each returns on top of the language
once the local, single-user story is excellent; none of it is built
toward from this tree.

One deferral has been partly taken back, deliberately: a compiled Luce
artifact links against a published C ABI (`docs/CODEGEN.md`).  It is
host-only — one entry point and a table of the same effects the
terminal already implements — but it is versioned in public and cannot
be changed casually.

## Roadmap

The build order and the memory model are their own documents:
`docs/ROADMAP.md` is the sequenced plan, and `docs/MEMORY.md` is the
model it builds toward — value and reference types with automatic
reference counting, "memory you never think about."

The language's foundations are in place, each live end to end:
collections and conversions (`docs/LANGUAGE.md`), modules (a file is a
module), methods and the string/sequence library, global constants,
**visibility** (public unless `private`, the unit the file —
docs/VISIBILITY.md), **the bit set** (`& | ^ ~ << >>` on `int`/`long`
at Go's precedence — docs/BITWISE.md), **the storage widths** (`byte`,
`short`, `half` store and convert but never compute — docs/TYPES.md),
**enums with `match`** (docs/ENUMS.md), **unions** (docs/UNION.md),
**function values** (docs/FUNCTIONS.md), and the **recoverable-error
story** — `T?`, `T!`, `try`, `catch`, `error(...)` (docs/FAILURE.md).

Code generation is finished: the LLVM backend is the only engine, the
lowering is **total**, a `.lc` *is* machine code, and `loom run` is one
`dlopen` (`docs/CODEGEN.md`, `docs/ENGINE.md`).  What is genuinely left
of it is named in `docs/CODEGEN.md`: cross-compilation (one
`libluce_rt` per target) and sharing one `libluce_rt` between artifacts
instead of copying it into each.

Ahead: finishing the reference-counted runtime and the `class`
reference type with `weak` (`docs/MEMORY.md`, `docs/ROADMAP.md`),
growing the terminal (bracketed paste, incremental drawing) and
userland, and — only after the local story is excellent — persistence.
