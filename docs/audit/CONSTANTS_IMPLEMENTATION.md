# Constants implementation audit

**Base:** `ae0f39fd728aeb3ae1b47161b76a612f0eab4bd8`
**Started:** 2026-08-08
**Scope:** the ratified `docs/CONSTANTS.md` run only.

This is the live closeout ledger for the constants implementation.  Every
oddity found while building the feature stays here until it is fixed,
retained deliberately, or moved to the living gap list.  The final
ratification table in `docs/CONSTANTS.md` is authoritative where the older
proposal text disagrees with it.

## As-built decisions

| ID | Decision | Disposition |
|---|---|---|
| C1 | Constant arrays keep Luce's rank-only type, written `array(T, _)`; the literal supplies the one runtime dimension.  The proposal's `array(T, 29)` would add a sized pseudo-type that the rest of the language does not have. | Chosen before implementation; record in the as-built appendix and living reference. |
| C2 | `{key: value}` is one expression in both runtime and `const` positions.  Runtime literals are fresh mutable maps; constant literals become one program-root object per written construction. | Chosen from R-B and the memo's one-grammar recommendation. |
| C3 | An unannotated integer map key lands on `long`, the only integer key type maps admit. | Required for the ratified `{0: "stored"}` example. |
| C4 | Duplicate keys in a constant map are a compile-time error naming both sites.  Runtime expressions keep ordinary ordered-map semantics: keys are evaluated in order and a later equal key replaces the earlier value. | Keeps dynamic expressions dynamic and uses the existing map operation. |
| C5 | Pool rows are not content-interned.  Repeated uses and defaults share their construction's handle; two separately written equal constants remain distinct because object equality is identity. | Required observable identity rule. |

## Findings

| ID | Finding | Status |
|---|---|---|
| F1 | The proposal body says ownerless/eternal, but ratified R-C says the program root owns constants and teardown is their death point. | Fixed with an explicit program owner and teardown sweep; living docs and the frozen record's as-built appendix state the correction. |
| F2 | `ConstantValue.absent` exists, but optional list/map/array elements are deliberately refused. | Retained: absence does not become a constant-container element. |
| F3 | The proposal's mutation inventory predates `list.sort_by`. | Fixed: direct and aliased visible roots refuse statically; a parameter-hidden root reaches `immutable_object` on both engines. |
| F4 | The six `std.zip` customers are CRC, four length/distance base/extra tables, and the dynamic code-length order table. | Fixed: all six are immutable top-level containers; the per-call builders were deleted and ZIP compiles against the shared rows. |
| F5 | Worker runtimes bypass root entry setup on both engines. | Fixed: interpreter and compiled worker entry paths materialize their own pruned pool in each child runtime; dual-engine worker specs cover it. |
| F6 | Existing runtime exports can create and fill only loose containers; none can install a program-root row. | Fixed with an internal begin/publish/load/finish/abort/discard service family; the published host ABI stays 13. |
| F7 | LLVM inlines object-free index stores and list append, bypassing runtime mutators. | Fixed end to end: unknown aliases retain the owner guard, final-MIR analysis removes it from proven-fresh rows, and F50/F58's final A/B is flat. |
| F8 | Current prune runs before dead-code compaction, so rows referenced only by dead instructions would still materialize. | Fixed: the constant pool compacts from surviving block items after dead-code removal and rewrites every `const_container` reference. |
| F9 | Container rows may refer to string data; pruning a row must not strand otherwise-unused encoded strings. | Fixed: row compaction marks encoded strings before the ordinary string-pool compaction and remaps nested constant atoms. |
| F10 | A materialization allocation can fail before a user frame exists, but the memo promises `allocation_failed` at the declaration. | Fixed: pool rows carry source origins, both engines emit the same synthetic declaration frame, and partial construction is cleaned before reporting. |
| F11 | Program-root ownership must survive forged bind/adopt/loosen/free operations and be excluded from the leak census while still being swept at teardown. | Fixed in the runtime owner state and verifier/backstop tests: program ownership is sticky, excluded from the live census, and swept only at runtime teardown. |
| F12 | Exactly 36 valid production top-level `let` declarations had to become `const`; embedded fixtures also contain intentional retired spellings. | Fixed: all 36 production declarations and the compile fixtures that exercise constants were migrated deliberately; retired-spelling refusals remain explicit tests. |
| F13 | The editor's manually mirrored vocabulary previously missed `spawn`; constants add a 33rd keyword. | Fixed for the shipped editor: both vocabularies are constant maps and include `const`; deriving them from compiler vocabulary remains the existing documented improvement. |
| F14 | Grammar, VS Code configuration, site highlighting, coverage, and docs all carry copied keyword/brace/constant inventories. | Fixed and verified: generated grammar/site tables include `const` and braces, coverage pins them, and the matching VS Code extension was packaged, installed locally and byte-compared with the worktree. |
| F15 | `docs/README.md` still calls CONSTANTS drafted, and living docs still describe only S1-S45 and 17 feature specs. | Fixed: CONSTANTS is ratified/built, ownership is S1-S46, and the registered executable surface is 18 spec packages. |
| F16 | F-string format-spec scanning had its own brace-depth counter: without teaching it map braces, a colon inside `f"{copy {"a": 1}}"` was mistaken for `:.Nf`. | Fixed in the parser lane and covered by a lexer regression. |
| F17 | Whitespace immediately inside an f-string hole (`f"{ x }"`) is rejected because the hole is re-lexed as a standalone buffer and leading space becomes indentation. | Deferred: pre-existing and not a constants semantic; recorded in `docs/MISSING.md`. |
| F18 | The lexer/parser barrel prose still says layout is suspended only by parentheses and calls `const` foreign, although their implementations now accept braces and file-scope `const`. | Fixed in both stage headers. |
| F19 | Inferred constant literals bypass written-type validation, so checking only `carriesObjects` would have admitted `list(T?)`/`map(K,T?)` through a named optional constant even though container types forbid optional parts. | Fixed in the folder: top-level optional elements are refused explicitly; an object-free struct may still contain an optional field. |
| F20 | `file.read(into)` mutates the destination byte array through a host effect, outside the ordinary receiver-method inventory. | Fixed end to end: stage 4 refuses direct/aliased visible roots, runtime guards the destination, and the parameter-hidden spec proves the host callback is never reached. |
| F21 | The module decoder's existing recursive type reader had no bound on forged repeated optional tags; constant-value decoding makes the same hostile-input boundary newly visible. | Fixed in the MIR lane by one shared decode-depth bound. |
| F22 | Function pruning conservatively scans a reachable function's raw instruction pool, so an orphan `const_function` can retain an otherwise dead function. | Fixed: dead instruction compaction now precedes function reachability pruning, so orphaned function references leave the pool before target functions are marked reachable; a verified-MIR regression pins the artifact boundary. |
| F23 | Constant-map duplicate detection initially repeated long/string equality instead of using the runtime's canonical `value.keyEquals` seam promised by the design. | Fixed: folded keys are viewed as borrowed runtime values and compared through `keyEquals`; the verifier applies the same byte-level key rule to decoded modules. |
| F24 | `append` has two ownership contracts behind one intrinsic: a list consumes its value, while a builder borrows text.  An immutable-object rejection must discard only the list operand or it can free borrowed builder input. | Fixed in the runtime lane with separate regressions for both shapes. |
| F25 | The leak census subtracts only top-level program roots because this run refuses nested constant containers.  If nesting is admitted later, program-owned child rows must be counted and swept by the same root policy. | Retained design boundary: flat constants only; the implementation dependency is recorded beside the future relaxation in `docs/MISSING.md`. |
| F26 | LLVM could not safely inspect the old auto-layout `Owner` tagged union: there was no stable field offset to publish. | Fixed: runtime ownership is an explicit `{ kind: enum(u32), binding }` representation and exports measured layout offsets; no host ABI change. |
| F27 | Failed materialization has two distinct resources: the current unpublished loose handle and any already-published roots. | Fixed in the runtime API by `discardLoose` for the current row followed by `abortConstants` for published rows; interpreter and LLVM OOM tests prove both cleanup paths. |
| F28 | Optional elements were correctly refused after F19, but initially reused the nested-container diagnostic and falsely claimed an optional “carries a list, map, array, builder, file, or task.” | Fixed: optional sequence elements/map values now receive an explicit flat-element diagnostic while optional fields inside object-free structs remain legal. |
| F29 | Provenance initially identified a root only by its bare declaration name.  That lost C5 identity across `const B = A`, and could conflate distinct imported constants with the same name. | Fixed: `RootState.constant` carries the canonical pool-row identity plus a display name; joins compare rows, so aliases of one construction stay known and distinct declarations never merge accidentally. |
| F30 | A worker-side interpreter arena allocation failure can reach `adoptTrap` without a pending trap and is then misreported as `host_unavailable`. | Fixed: the interpreter marks the worker runtime exhausted when its call path catches `OutOfMemory`, and the shared join propagates that marker as `error.OutOfMemory`; runtime and interpreter regressions cover both seams. |
| F31 | Private structural tests in `interpreter/machine.zig` were not registered by the interpreter package test block, so they could compile without ever running. | Fixed in the interpreter lane by importing `machine` explicitly from `interpreter.zig`'s test block; the constants boundary tests now run. |
| F32 | The LLVM lowering header still described the retired `i1` trapped flag even though calls now return the `i32` Outcome ABI. | Fixed in the implementation header; no behavioral change. |
| F33 | `runtime/trace.zig` said the function-info table had exactly one row per Luce function, but constant materialization needs synthetic declaration rows after the real functions. | Fixed: the trace contract now permits synthetic rows after real functions, matching both engines' declaration frames. |
| F34 | Unwind capping counted only the current interpreter worker stack, so frames already adopted from a nested worker could make a trace exceed `trace.max_frames`. | Fixed while adding constant prelude frames: the remaining-room calculation now includes adopted and prelude frames. |
| F35 | The release-path dual-engine harness calls `mir.strip(&compiled)` twice in succession. | Closed in the current harness: each source-based release entry point strips its own freshly compiled program once, while `runProgram` accepts an already prepared program and performs no stripping; the current call-site audit finds no double strip. |
| F36 | Unary constant folding initially widened every negation to `long`/`double` and left `~byte`/`~short` at storage width, disagreeing with runtime arithmetic promotion and binary32 rounding. | Fixed: unary folds now compute at `Type.arithmeticType()`, enforce the matching width's overflow boundary, and round float results at binary32. |
| F37 | Joining two different statically visible constant roots initially produced the same `unknown` state used for a parameter-hidden value, so a known A-or-B alias escaped the static mutation gate. | Fixed: root flow has a distinct `maybe_constant` taint; unequal visible roots remain statically immutable while true boundary-unknown values retain the runtime backstop. |
| F38 | A nested store through `module.PRIVATE_CONSTANT[...]` looked up the pool row before applying imported visibility and could reveal a private declaration through a constants diagnostic. | Fixed: written constant-place resolution is tri-state and applies the ordinary `luce.sema.private` gate before returning provenance. |
| F39 | Constant trace rows use `functions.len + container_index` through a `u32` trace-frame index, while MIR verification bounded each table separately and left the combined count implicit. | Fixed: verification now refuses a combined description count beyond `u32`, with boundary tests, before walking either table. |
| F40 | LLVM materializes a constant array of value structs through the stable array API by filling every cell with a zero struct, then replacing every cell with its folded value. | Deferred in `docs/MISSING.md`: correct and cleanup-safe, but a future bulk/final-content constructor could avoid the duplicate storage work. |
| F41 | Loop widening preserved visible immutability when the loop entered with a constant alias, but a mutable local first assigned a constant on one iteration could re-enter the next iteration as a program root before an earlier mutation. | Fixed in stage 4 with a small, control-conservative visible-root fixed point before loop lowering; a two-iteration refusal and fresh-only non-taint regression are assigned to the spec matrix. |
| F42 | A present value inside an optional field of an object-free folded struct was rejected even though `none` worked: the folder implemented numeric widening but not the language's `T` to `T?` fit.  The same omission affected present optional constants and folded defaults. | Fixed with one folded-value fitting seam shared by declarations, defaults, and struct construction; stage 4 now emits present folded optionals as payload plus `optional_wrap`, while the pool encoding continues to reserve `.absent` for absence. |
| F43 | The editor customer was migrated from a fenced string to constant maps, but its adjacent design comment still claimed constant containers did not exist and still counted the pre-`const` keyword set. | Fixed in the production source: the comment now describes the immutable map lookup and the compiler's 33-keyword table. |
| F44 | After adding folded `T` to `T?` fitting, a bare literal in a storage-width optional (`byte?`, `half?`, and their peers) still landed at the default `int`/`float` before fitting, unlike ordinary expression lowering. | Fixed by sharing one `literalLandingType` rule between ordinary lowering and constant folding; optional storage places now supply their payload width before parsing and wrapping. |
